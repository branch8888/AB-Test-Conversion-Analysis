# 电商落地页转化率 A/B Test 分析与决策

某电商平台 2017 年 1 月的落地页改版实验，294,478 条曝光记录。用 Python 完成数据审计、效果估计、推断稳健性检验、样本量能力评估和决策建议。

[分析 Notebook](notebooks/ab_test.ipynb) · [HTML 报告](reports/ab_test_report.html) · [Tableau Dashboard](https://public.tableau.com/views/ABtest_17871506401860/1?:showVizHome=no)

## 结论

| 问题 | 结论 |
|---|---|
| 数据质量 | 23 天分流比例正常。3,893 条分组与页面不匹配的记录来自两处系统性错位，清洗后不损失任何用户 |
| 效果 | 转化率 12.0386% → 11.8808%，差 -0.1578 个百分点（相对 -1.31%），95% CI [-0.394%, +0.078%] |
| 显著性 | $p=0.1899$，六种方法结论一致；A/A 校准的假阳性率 4.92%，检验本身正常 |
| 实验能力 | 只能检出 ≥2.80% 的相对提升，1% 的提升检出概率 17% |
| 决策 | 不上线。贝叶斯期望损失 0.163 pp vs 0.005 pp；非劣效检验在 0.2 pp 界值下未通过 |

结论的表述方式是：本轮实验分不清"新页面没有提升"和"新页面有小幅提升"。在现有样本量下得到不显著的结果，信息量很低，不足以说新页面无效。要回答 1% 量级的改版问题，需要先解决样本量和埋点两件事。

## 分析内容

**数据审计。** 先确认数据能不能用。分流比例做了全期和按日两种卡方检验，23 天里没有一天超出 Bonferroni 校正后的阈值。重复上报的 3,894 位用户分成两类：1,895 人同一页面、两个分组标签（页面没变，分组标签重新写过），1,998 人同一分组、两个页面（分组没变，页面被串）。3,893 条错配记录正好等于 1,895 + 1,998，是这两类用户各有一条与分配版本不符的记录。清洗只删记录不删用户，294,478 行降到 290,584 行，用户数不变。

顺带发现这批重复上报用户的转化率是 13.05%，其余用户 11.94%（$z=2.10$，$p=0.036$）。他们不是随机子集，所以清洗规则本身需要做口径对照。

**效果估计与稳健性。** 用 z 检验、卡方（含 Yates 校正）、Fisher 精确检验、logistic 回归（HC3）、置换检验、bootstrap 六种方法算同一个问题，$p$ 值都在 0.18–0.19 之间，没有一种接近 0.05。再用 A/A 校准确认检验本身没有偏：把 control 组随机分成两半跑 5,000 次，假阳性率 4.92%（名义 5%），区间覆盖率 95.08%（名义 95%）。

**样本量能力。** 当前每臂约 14.5 万人，MDE 是 0.3373 个百分点，即 2.80% 的相对提升。业务关心的是 1% 量级，这个量级在当前样本量下只有 17% 的检出概率。要做到 80% 功效，每臂需要 115 万人，按 12,634 人/天要跑 182 天，而实际只跑了 22 天。

**时间维度。** 日效应的线性趋势 $p=0.987$，前后两个 7 天窗口的效应量接近，没有新颖性效应的迹象。按天分块前后的标准误只差 0.01%，因为随机化单位是用户、每人只在一个自然日内出现一次，日间差异本来就被随机化平衡掉了。

**序贯风险。** 用真实时间轴模拟了每天观察的后果：只做一次最终检验时假阳性率 5.75%，每天都看时升到 28.00%。随后用 mSPRT 构造任意时点有效的置信序列（闭式解，对效应量取高斯混合先验），最终区间 $[-0.53\%, +0.21\%]$，比常规区间宽 1.58 倍，但仍然跨 0。

**决策层。** 把"更好吗""不劣于吗""等价吗"三个问题分开算。非劣效检验在 0.2 pp 界值下不通过，界值放宽到 0.4 pp 才勉强通过；等效性检验在 ±0.3 pp 下不通过。贝叶斯后验给出 P(新页面更好) = 9.5%，上线的期望损失 0.163 pp，不上线 0.005 pp。

**敏感性。** 主口径、ITT、as-treated、剔除跨组用户、剔除首尾半天、仅前 7 天、仅后 7 天、按天分块，八种口径的效应量在 -0.147 到 -0.219 pp 之间，方向一致，全部不显著。

所有模拟（置换 50,000 次、bootstrap 20,000 次、A/A 5,000 次、偷看 2,000 次、覆盖率 500 次、贝叶斯 40 万抽样）只用于检查方法本身，不参与结论。结论数字全部来自真实的 290,584 位用户数据。

## 分析边界

- 没有订单金额、利润或商品信息，结论只讨论转化率，不涉及收入。
- 没有设备、渠道、地域等用户属性，无法做异质性分析或 uplift 建模。
- 没有实验前行为数据，无法做 CUPED 一类方差缩减。按天分块的标准误只降了 0.01%，说明这条路在这份数据上走不通。
- 只有一个指标，没有护栏指标。真实上线决策需要护栏指标配合。
- 非劣效和等效的结论依赖界值选择。界值应来自业务成本核算，且必须在实验开始前登记，事后调整等同于 p-hacking。
- 没有处理多重比较。若同时检验多个指标或多个分群，$\alpha$ 需要相应调整。
- GitHub 会过滤 Notebook 里内嵌的 Tableau `iframe`，交互看板请从本文顶部的链接打开。
